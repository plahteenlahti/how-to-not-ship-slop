Trends · takeaway
Droidcon USA · 2026
The short version

Three things to remember about app monetization trends.

01 · acquireAndroid's gap starts before the trial.

Once users start a trial or pay, their conversion and value look much closer to iOS.

02 · retainConversion is not retention.

Paywalls and trials change purchases. Recurring product value decides renewal.

03 · operateMonetization is a system.

Billing recovery, entitlements, web checkout, support, and policy must keep working together.

Ads
Droidcon USA · 2026
Monetization at scale

Ads are simple, but scale-dependent.

  • Easy to implement; works for completely free apps
  • You need massive volume to make meaningful money
  • Ads can hurt the UX and damage your brand
Consumables
Droidcon USA · 2026
Pay as you go

Consumables are things users can buy again.

  • Extra lives, credits, tokens, tips, or storage
  • A flexible and user-friendly entry point
  • Revenue depends on repeat buying
Subscriptions
Droidcon USA · 2026
Recurring revenue

Subscriptions are the gold standard — if value keeps recurring.

  • Predictable income and stronger user commitment
  • Free trials, intro offers, and regional pricing
  • Stop improving and users will quickly churn
Virtual currency
Droidcon USA · 2026
Credits, tokens, minutes

Virtual currencies let you build your own economy.

  • A strong fit for AI/ML, games, and creative tools
  • Sell credits that users spend inside the app
  • Subscribers can get monthly credits and top up

01 · Configure
Droidcon USA · 2026
Application.onCreate()

Initialize once, as early as possible.

Use the public Google SDK key. Never ship a secret API key in the app.

class MainApplication : Application() {
  override fun onCreate() {
    super.onCreate()
    Purchases.logLevel = LogLevel.DEBUG
    Purchases.configure(
      PurchasesConfiguration.Builder(
        this, "goog_public_sdk_key"
      ).build()
    )
  }
}

Recovery
Droidcon USA · 2026
Restore purchases

Give customers a way to recover access.

  • Trigger restore from an explicit customer action
  • Refresh the entitlement state when it succeeds
  • Show the App User ID in support diagnostics
Purchases.sharedInstance.restorePurchasesWith(
  onError = { error ->
    showRecoveryError(error)
  },
  onSuccess = { customerInfo ->
    val restored = customerInfo
      .entitlements["pro"]
      ?.isActive == true
    updateAccess(restored)
  }
)

Policy architecture

Rules change

Keep checkout routing remotely configurable.

  • Inputs: region, program enrollment, app version, eligibility
  • Output: Play Billing, user choice, or permitted external route
  • Ship a safe default when configuration is missing
