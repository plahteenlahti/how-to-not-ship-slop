Trends · takeaway
Droidcon USA · 2026
The short version

Three things to remember about app monetization trends.

01 · acquireThe biggest Android gap comes before payment.

Once someone starts a trial or pays, Android looks much closer to iOS.

02 · retainA first purchase does not guarantee a renewal.

The paywall gets the sale. The product earns the next payment.

03 · operateGetting paid takes ongoing work.

You still need billing recovery, entitlements, support, web checkout, and policy updates.

Ads
Droidcon USA · 2026
You need a large audience

Ads are easy to add. Making real money from them is harder.

  • They let the app stay completely free
  • A small or niche audience will not produce much revenue
  • Too many ads can make the app worse to use
Consumables
Droidcon USA · 2026
Pay as you go

Consumables are things customers can buy more than once.

  • Extra lives, credits, tokens, tips, or storage
  • Customers can spend a little without starting a subscription
  • You only earn more when they come back and buy again
Subscriptions
Droidcon USA · 2026
Recurring revenue

Subscriptions work when the app keeps earning the next payment.

  • Revenue becomes more predictable
  • You can use trials, introductory offers, and regional pricing
  • If the product stops improving, customers leave
Virtual currency
Droidcon USA · 2026
Credits, tokens, minutes

Virtual currency lets customers pay for small units of value.

  • Useful for AI tools, games, and creative apps
  • Customers buy credits and spend them inside the app
  • A subscription can include credits with paid top-ups

The implementation trap
Droidcon USA · 2026
The boring stuff that breaks

You do not build billing once and forget about it.

AvailableProducts load with localized prices and eligibility.
PendingThe customer confirms in Google Play — possibly in another app.
PurchasedThe transaction is verified and acknowledged.
EntitledCustomerInfo unlocks the experience on every device.
RecoveringGrace period, billing retry, restore, and offline cache.
RevokedExpiry, refund, cancellation, or account mismatch.
API changes and edge cases can break purchases and cost real money.

01 · Configure
Droidcon USA · 2026
Application.onCreate()

Initialize once, as early as possible.

Use the public Google SDK key. Never ship a secret API key in the app.

class MainApplication : Application() {
  override fun onCreate() {
    super.onCreate()
    Purchases.logLevel = LogLevel.DEBUG
    Purchases.configure(
      PurchasesConfiguration.Builder(
        this, "goog_public_sdk_key"
      ).build()
    )
  }
}

Offerings
Droidcon USA · 2026
What is an offering?

An offering is the set of products you want to sell right now.

  • It can include monthly, annual, lifetime, or consumable packages
  • You can switch from the standard offer to a promotion
  • Your app still needs to handle the case where no offering loads
val offering = try {
  Purchases.sharedInstance
    .awaitOfferings()
    .current
} catch (e: PurchasesException) {
  logger.warn(e) { "Offerings unavailable" }
  null
}

val annual = offering
  ?.annual
  ?.storeProduct

Recovery
Droidcon USA · 2026
Restore purchases

Give customers a way to recover access.

  • Trigger restore from an explicit customer action
  • Refresh the entitlement state when it succeeds
  • Show the App User ID in support diagnostics
Purchases.sharedInstance.restorePurchasesWith(
  onError = { error ->
    showRecoveryError(error)
  },
  onSuccess = { customerInfo ->
    val restored = customerInfo
      .entitlements["pro"]
      ?.isActive == true
    updateAccess(restored)
  }
)

Policy architecture
Droidcon USA · 2026
Rules change

Let the server decide which checkout route the app shows.

  • Check the region, program enrollment, app version, and eligibility
  • Choose Play Billing, user choice, or an allowed external route
  • Fall back to Play Billing when the configuration is missing
when (checkoutConfig.route) {
  PLAY_BILLING -> showPlayPaywall()
  USER_CHOICE  -> showBillingChoice()
  EXTERNAL_WEB -> openApprovedLink()
  else        -> showPlayPaywall()
}

// Route config comes from your backend.
// Re-check policy before every release.
