Google · Android Publisher API
import { google } from 'googleapis';

// Auth and client setup omitted
const publisher = google
    .androidpublisher('v3');

async function validateGoogle(purchaseToken) {
  const { data } = await publisher
      .purchases.subscriptionsv2.get({
        packageName: 'com.example.app',
        token: purchaseToken,
      });

  return [
    'SUBSCRIPTION_STATE_ACTIVE',
    'SUBSCRIPTION_STATE_IN_GRACE_PERIOD',
  ].includes(data.subscriptionState ?? '');
}

Future<void> initPlatformState() async {
  await Purchases.setLogLevel(LogLevel.debug);

  late PurchasesConfiguration configuration;
  if (Platform.isAndroid) {
    configuration = PurchasesConfiguration(
      '<revenuecat_project_google_api_key>',
    );
  } else if (Platform.isIOS) {
    configuration = PurchasesConfiguration(
      '<revenuecat_project_apple_api_key>',
    );
  } else {
    return;
  }

  await Purchases.configure(configuration);
}

But what’s even cooler is that we can give users a trial or in-app currency when they watch an ad. This is called a rewarded ad.

RevenueCat Ads does two things. It tracks ad revenue against the same user as your subscription and IAP data, so total revenue and realized LTV include ads. It also grants rewards for watching a rewarded ad: either virtual currency or a timed Entitlement, verified server-side through AdMob.

A user finishes a rewarded ad, AdMob fires a server-side verification (SSV) callback to RevenueCat, and RevenueCat verifies it and grants the reward. You don't build the verification layer. You don't build the granting layer. You just configure it in the dashboard.

Two kinds of rewards: virtual currency — coins, credits, gems, tokens, whatever your economy uses. Entitlements — actual RevenueCat Entitlements, granted for a duration.
